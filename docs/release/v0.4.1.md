# cli-bot v0.4.1

A reliability release. Nothing about the v0.4.0 safety model changes; these
are the seven runtime problems a code review found, fixed.

## One bad session file no longer stops everything

`cli-bot` pruned expired sessions on every run, by parsing each file, and
gave up on the first one it could not read. A file half-written by an
interrupted run, or edited by hand, therefore broke `--check`,
`--no-session`, `--session-clear` and `--session-list` — every command you
would reach for to recover.

Now an unreadable file is skipped and reported under `--verbose`, never
deleted. Pruning uses each file's modification time, so it needs no parse at
all, and runs only when the invocation actually uses session memory.

Session files are also written through a temporary file and a rename, so an
interrupted write cannot leave a half-written one behind.

## Session history is owner-only

On Unix the sessions folder is now created `0700` and each file `0600`. They
hold your requests, the commands chosen, working directories and, when you
enable capture, command output; they were world-readable at `0644`. A file
left wider by an earlier version is narrowed when it is next written.

## Planner timeouts are yours to set

Every planner call used to fail after a fixed 30 seconds, which is less than
a first load of a large model takes. In this project's own benchmark, 11 of
35 calls failed that way.

```toml
[ollama]
request_timeout_seconds = 300   # 0 removes the limit
connect_timeout_seconds = 10    # short, so an Ollama that is not running fails at once
```

## Interactive mode survives a bad answer

A planner timeout or an unparsable reply used to end the whole session.
Error kinds are now distinguished by type rather than by matching the text
of a message, so an interactive session prints the error and asks again.
Reaching the end of input ends the session cleanly.

## A failed command keeps its status

A command that exits non-zero now:

- reports `command exited with status 3`, rather than
  `command exited with status exit status: 3`;
- is saved in session memory, so a follow-up such as "why did that fail" has
  the context;
- lends `cli-bot` its own exit status, so scripts see the real code.

**If you check `$?`,** this is the change to know about: `cli-bot` used to
exit 1 for every failure. Its own failures still do.

## Capturing output no longer breaks your editor

With `capture_command_output = true`, commands ran with no terminal at all,
so editors, pagers, `ssh` and password prompts could not work and nothing
appeared until the command finished. Now standard input is always the
terminal's, captured output is written out as it arrives, and a command that
draws on the terminal itself runs without capture instead of being broken.

## Session names survive a toolchain upgrade

Working-directory session files were named with the standard library's
`DefaultHasher`, whose algorithm may change between Rust releases, orphaning
your sessions. They now use a fixed hash, and a file under the old name is
found once and renamed.

## Upgrading

```bash
cargo install cli-bot --force
```

Existing configuration files and session files keep working. The two new
`[ollama]` keys have defaults, and a session file written by any earlier
version still loads.
